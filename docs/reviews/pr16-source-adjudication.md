## D17: precise direction and coverage

Printed p.316 gives9.2 as: y is a species/part of X; X has A; therefore y has A,
with additional comparative alternatives. Printed p.317 gives10.1 as:
X has a property; therefore all its parts have that property. **Both point
from whole to part.** An objection that they have opposite directions would
be inaccurate, and this review rejects that objection as well.

They are nevertheless not interchangeable executable records. One identifies
a particular member and its relation to the whole; the other produces an
aggregate universal property claim under its division profile. The aggregate
does not become each typed member's property without an appropriate bridge,
and it supplies none of9.2's comparison variants. The implemented physical,
species-degree, physical-degree, and smaller-part records make those branches
explicit instead of claiming their coverage from10.1 alone.

The positive10.2 form points in the other direction: a selected part has A,
therefore the whole has A. Its printed second premise says only-if. That is
a necessary-condition statement, not the sufficient condition needed for the
positive branch. The continuation correctly requires an explicit sufficiency
warrant for that branch; the negative branch separately requires a complete
partition and evidence that no part has A. The follow-up's description that
10.2 makes any part carry a whole's property does not accurately describe
that printed direction.

## The authored33.4 correction

The schema and CQ1 are printed on p.332; CQ2–CQ3 continue on p.333. The supplied
page facsimile was inspected (`scope-audit/book-342.png`, PDF page342).
The old default strengthened the source premise into a uniformly strong
likelihood claim. The new default is:

```text
omission_consequence_likelihood_adequate(X,C)
```

It means that the assessed likelihood of C **from not doing X** is adequate
for the strength of this prudential argument. Its distinct identity is
essential: using the positive-action predicate
`consequence_likelihood_adequate(X,C)` directly would identify doing X with
omitting X. Neither assessment automatically answers the other's challenge.
No numerical probability or threshold is calculated or manufactured.

The two ordinary premises, the conclusion, and CQ3's supported exception are
unchanged. The old `strongly_occur` template is removed from the current
library; saved judgments about it require manual semantic migration. A
positive old threshold, its negation, and an unanswered question are all left
for explicit review instead of being automatically renamed.

Nine live-library cases cover the threshold distinction, unanswered and
answered adequacy, an obsolete answer, wrong action and outcome, both
doing/omitting separation directions, and survival of the original supported
exception. The existing exact `/book` example remains. A validator instance
and a three-polarity migration test pin the same source distinction.

The prior33.4 approval is removed and the row returned to
`transcription-checked` pending non-author review. This temporarily changes
the author worktree to127 approved and16 held; it does not prejudge the
reviewer's result. The current register, manifest and final acceptance must
be refreshed after integration and independent source approval.
